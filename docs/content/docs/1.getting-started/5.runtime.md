# Validate content on the server

Import `@lupinum/ginko-editor/runtime` when a backend needs to validate an editor
document or prepare a content checkpoint. This entry shares its schema and
conversion code with the visual editor. It does not import Vue views, styles,
or browser globals.

```ts
import {
  createEditorSchema,
  prepareMarkdownForVisualEditing,
  convertTiptapDocToMarkdown,
} from '@lupinum/ginko-editor/runtime'

const schema = createEditorSchema()
const prepared = await prepareMarkdownForVisualEditing(source, undefined, schema, authoringKit)
if (!prepared.ok || !prepared.value) {
  throw new Error('This source needs source editing.')
}

const document = schema.nodeFromJSON(prepared.value)
document.check()
const checkpoint = await convertTiptapDocToMarkdown(document.toJSON())
if (!checkpoint.ok) {
  throw new Error('The document cannot be saved as portable content.')
}
```

Use the same authoring kit and output options as the host editor. Components,
properties, and slots remain subject to the shared Content policy. Inspect
the returned `issues` to explain a rejected conversion. Never replace failed
content with an empty document.

The schema describes supported node structure. A structurally valid document
can still contain values that fail a host's content policy. Validate both before
accepting a checkpoint. Authorization, version checks, storage, and document
identity belong to the host. This entry does not provide a collaboration server.

The runtime uses the package's pinned TipTap dependencies. Use the same package
version on the server and client when exchanging editor documents.
