# Validate content on the server

Import `@lupinum/ginko-editor/runtime` when a backend needs to validate an editor
document or prepare a content checkpoint. This entry shares its schema and
conversion code with the visual editor. It does not import Vue views, styles,
or browser globals.

```ts
import {
  createEditorSchema,
  prepareMarkdownForVisualEditing,
  convertTiptapDocToMarkdown,
} from '@lupinum/ginko-editor/runtime'

const schema = createEditorSchema()
const prepared = await prepareMarkdownForVisualEditing(source, undefined, schema, authoringKit)
if (!prepared.ok || !prepared.value) {
  throw new Error('This source needs source editing.')
}

const document = schema.nodeFromJSON(prepared.value)
document.check()
const checkpoint = await convertTiptapDocToMarkdown(document.toJSON())
if (!checkpoint.ok) {
  throw new Error('The document cannot be saved as portable content.')
}
```

Use the same authoring kit and output options as the host editor. Components,
properties, and slots remain subject to the shared Content policy. Inspect
the returned `issues` to explain a rejected conversion. Never replace failed
content with an empty document.

The schema describes supported node structure. A structurally valid document
can still contain values that fail a host's content policy. Validate both before
accepting a checkpoint. Authorization, version checks, storage, and document
identity belong to the host. This entry does not provide a collaboration server.

The runtime uses the package's pinned TipTap dependencies. Use the same package
version on the server and client when exchanging editor documents.

## Preserve property changes

`createEditorSchema()` also registers `SetNodePropertyStep` and
`SetComponentVariantStep`, and `SetNodeAttributeStep` for decoding editor operations. The canvas uses the
property step for individual component settings, titles,
and column sizes. A step changes one property on the current node. It keeps
other properties and the node's current body.

```ts
import { SetNodePropertyStep } from '@lupinum/ginko-editor/runtime'

const step = new SetNodePropertyStep(position, 'title', 'A useful title')
const wireValue = step.toJSON()
```

Use `undefined` to remove a property and `null` to store a null value. The wire
format uses an explicit removal flag. Independent property changes survive
rebasing, which adjusts pending operations after another edit. For two changes
to the same property, the last accepted operation wins. This is a field update,
not character-by-character collaboration within a title input. Consecutive typing
in one property field forms an undo group. Variant changes keep the tag and its
source metadata together while preserving other properties and body text.

The step validates its wire shape. The host must still validate the resulting
document against the Content policy and enforce authorization. Deploy clients
and servers that understand `ginkoSetNodePropertyV1` together before exchanging
these operations. Variant changes use `ginkoSetComponentVariantV1`. Older clients
cannot decode these steps.

`SetNodeAttributeStep` uses `ginkoSetNodeAttributeV1` for schema attributes such
as a code block's language or filename. It changes one declared attribute and
preserves the other attributes and current body. Component properties still use
`SetNodePropertyStep`.

For shared documents, use the [collaboration boundary](/docs/getting-started/collaboration)
to validate exact-version batches and produce source checkpoints.

## Enforce a content profile

The editor's `profile` prop limits what a writer can create. The editor does
not change content that it loads, and a writer can still use the source view of
the default variant. Check the profile again where you store the document.

```ts
import { createEditorSchema, findProfileViolations } from '@lupinum/ginko-editor/runtime'

const violations = findProfileViolations(document.toJSON(), 'inline')
if (violations.length) {
  throw new Error(`Remove ${violations.map(item => item.type).join(', ')} from this text.`)
}
```

`findProfileViolations` accepts TipTap JSON or a ProseMirror node. Each entry
has a `kind` (`node` or `mark`), a `type`, and, for a heading, its `level`.
`editorProfiles` contains the allowed node and mark names of each profile.
`sanitizeFragment(fragment, schema, profile)` reduces content to a profile in
the same way as paste.
