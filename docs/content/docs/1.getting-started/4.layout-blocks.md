# Layout blocks

The editor includes a layout kit. It contains the Ginko Docs components, for
example callouts, tabs, accordions, steps, cards, and timelines. The kit uses
the Ginko Docs component policy without changes. A document that you write
with this kit renders on a Ginko Docs site.

## Add the kit

Import the kit from the `authoring` entry. It has no Vue dependency, so you can
also use it on a server.

```ts [authoring.ts]
import {
  composeAuthoringKits,
  createGinkoLayoutKit,
  ginkoLayoutKitSource,
} from '@lupinum/ginko-editor/authoring'

// The layout kit alone.
export const layoutKit = await createGinkoLayoutKit()

// The layout kit and your own components.
export const kit = await composeAuthoringKits(ginkoLayoutKitSource, hostKitSource)
```

Pass the kit to the `authoring-kit` property of `GinkoEditor`. Each component
tag can occur in one source only. Do not compose this kit with another kit that
also defines the Docs tags.

Your reading site must render the same tags. A Ginko Docs site renders them
with its `Mdc*` components. `ginkoLayoutComponentNames` lists the component
name for each tag. `ginkoLayoutComponentPolicy` is the policy for your Content
configuration.

## Insert a block

Type `/` or select **Insert**. The layout blocks are in the **Layout**,
**Callouts**, **Media**, **Text**, and **Advanced** groups. Each recipe inserts
a complete example that you can change:

- **Tabs** inserts two tabs.
- **Accordion** inserts two items.
- **Steps** inserts three steps. Each level-three heading starts a step.
- **Cards** inserts a grid with two cards.
- **Timeline** inserts two events.
- **Code group** inserts two code blocks with file names.

## Edit containers

Tabs, accordions, steps, cards, timelines, code groups, code trees, and quizzes
are containers. The canvas shows their items and an add control.

| Container | On the canvas |
| --- | --- |
| Tabs | A tab strip above the content. Select a tab to show and edit its content. **+** adds a tab after the selected tab. |
| Code group | A tab strip with the file name or language of each code block. **+** adds a code block. |
| Accordion | Each item has an editable title. The arrow collapses an item in this view only. |
| Steps | A number beside each level-three heading. **Add step** adds a heading and a paragraph at the end. |
| Cards | A grid with the number of columns from the `cols` property. |
| Timeline | A marker beside each event. |
| Code tree, quiz | A list of items with an add control. |

Use the tab strip with the keyboard:

- The arrow keys, Home, and End select a tab.
- Enter or the Down arrow moves the caret into the tab content.
- F2 or a double-click renames a tab. Enter saves the name. Escape cancels.
- Delete removes a tab.

When a tab or an item has content, the remove control asks for a second
selection to confirm. A container always keeps one item. To remove the last item,
remove the whole block from its settings.

Each add, remove, and rename is one change. One Undo reverses it. Each change
must pass the Content policy, like all other component edits. When the policy
rejects a change, the document stays the same and the canvas shows a message.

The selected tab and collapsed accordion items are view state. They are not
saved in the document, in the undo history, or in collaboration steps. When the
caret moves into a hidden tab, that tab becomes visible.

When the caret is inside a tab or an item, the block menu shows the add action
of that container first, for example **Add tab**.

## Block reference

| Block | Tags | What you can edit | Limits |
| --- | --- | --- | --- |
| Callouts | `note`, `info`, `warning`, `error`, `success`, `idea` | Title on the canvas, icon, appearance, and content. Switch between callout types in the settings. | None. |
| Aside, excerpt | `aside`, `excerpt` | Label on the canvas, source, appearance, and content. | None. |
| Columns | `layout`, `column` | Content of each column. The divider sets both widths. | A column must stay inside a layout. |
| Tabs | `tabs`, `tab` | Tab names, tab icons, layout, padding, and tab content. | The editor shows one tab at a time. |
| Accordion | `accordion`, `accordion-item` | Item titles, item values, open items (JSON), and content. | The `title` and `content` slots are kept but have no separate editor. |
| Steps | `steps` | Step headings, step content, and mode. | Only level-three headings start a step. |
| Cards | `cards`, `card` | Card titles, descriptions, links, icons, images (URL), and content. | The `title`, `description`, and `footer` slots have no separate editor. |
| Timeline | `timeline`, `timeline-item` | Event titles, dates, labels, icons, the current event, and content. | None. |
| Code group | `code-group` | Code, language, and file name of each code block. | Only code blocks are items. |
| Code tree | `code-tree` | Code blocks with file paths, the selected file, and folder expansion. | The canvas shows a list, not a file tree. |
| Files | `files` | The file list, the highlighted path, and annotations (JSON). | The canvas shows the Markdown list. |
| Collapse | `collapse` | Content and appearance. | The canvas always shows all content. |
| Center | `center` | Size, maximum width, style, and content. | None. |
| Figure | `figure` | Image URL, alternative text, caption, aspect, fit, size, bleed, and zoom. | Enter the image URL in the settings. The image picker does not fill it. |
| Drop cap | `dropcap` | Number of lines (JSON) and content. | The canvas does not show the large letter. |
| Keyboard key | `kbd` | The key text in a sentence. | Inline only. |
| Read more | `read-more` | Title and links (JSON). | The canvas shows no link list. |
| Table of contents | `toc` | Title, depth (JSON), and open state (JSON). | The canvas does not show the headings. |
| Quiz | `quiz`, `quiz-question` | Quiz text and labels, questions, choices (JSON), and explanations. | The canvas does not check answers. |
| API reference | `api` | Title, icon, method, path, and groups (JSON). | The Docs renderer shows only the groups. It does not show block content. |

The Markdown image is the editor's own image block. The Docs `img` renderer shows
it. It is not part of this kit.

## JSON properties

Some properties hold structured data, for example read-more links or quiz
choices. Their settings field accepts JSON text. The editor applies the value
only when the text is valid JSON. When the text is not valid, the field shows an
error and the document keeps the previous value. You cannot clear a required
JSON property.

```json [Quiz choices]
[
  { "text": "Descriptive alternative text", "correct": true },
  { "text": "A longer file name", "correct": false }
]
```

## Source syntax

The recipes use the colon syntax of the Docs examples, for example `::tabs`.
Colon syntax stores number and boolean properties as text. When a block has
such a property, the editor saves that block with angle syntax, for example
`<Toc :depth="2" />`. The property then keeps its type, and the Docs policy
accepts it. The block renders the same way.
