# Get started with Ginko Editor

A portable Vue editor for Ginko content.

## Install

```bash
pnpm add @lupinum/ginko-editor @lupinum/ginko-content @tiptap/core @tiptap/pm @tiptap/vue-3 vue
```

## Use the package

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { GinkoEditor } from '@lupinum/ginko-editor'
import '@lupinum/ginko-editor/style.css'

const source = ref('# Hello\n')
</script>

<template>
  <GinkoEditor v-model="source" :enable-images="false" :enable-files="false" :enable-video="false" />
</template>
```

The Markdown source is the canonical value. Opening the editor and changing
modes do not rewrite it. The editor keeps invalid or unsupported documents in
source mode so that visual editing cannot discard content.

## Write and insert blocks

Type `/` at the start of a paragraph, or select **Insert**. Search for a block,
use the arrow keys to choose it, and press Enter. Escape closes the menu and
returns focus to the document. Normal headings, lists, quotes, code, dividers,
tables, and image requests are available without a component kit.

An `authoring-kit` adds the host's component recipes to the same menu. Recipe
`keywords` provide aliases such as `/note`. An optional `description` explains
what the recipe does. Component titles and labels appear on the writing canvas;
edit a title directly, or open the block’s cog to change its properties, switch
callout type, duplicate it, or delete it. Two-column layouts have a divider that
snaps to three width pairs; drag it or use the arrow keys. Table row and column
actions appear in small icon menus beside the active table.

The `recipe-preview` slot receives `{ recipe }`. Use `recipe.source` with Ginko
Content's parser, the kit's policy, and your own registered render components to
show the real component. The editor does not import host components or choose
how they render. The playground demonstrates this integration,
including a component library and a live reader preview.

## Save and select assets

Your application owns saving and asset storage. For inline uploads, pass an
`image-upload` callback; it receives `(file, { signal })` and resolves with a
durable `{ url, alt }`, or an `{ id }` resolved by `asset-provider`. Add image,
`/image`, and Replace image use a drop zone with a file chooser. The editor accepts
one image per placeholder, up to 10 MB by default. Set `image-max-bytes` to change
the limit. Reject to show an error and allow retry.
Respect the signal to cancel abandoned uploads.

You can also drop a file onto the editor without inserting a placeholder first.
Confirm Add image, or drop onto an existing editor image and confirm Replace
image in a popover attached to that image without moving the document. Cancel
leaves the document unchanged. To accept drops across a larger
workspace, pass its element as `image-drop-target`; drops outside the editor
append to the document. Other nested editors retain their own drop handling.

Unfinished uploads count as pending changes and block `flush()` with
`image_upload_pending`. Finish or remove them before leaving. The docs playground
stores images locally in this browser; a production host supplies durable storage.

Add `image-picker` to browse existing images in the same add/replace flow. It
receives `{ signal, current? }` and resolves a stored image reference, a durable
URL, or `null` on cancellation. `GinkoImagePicker` supplies a controlled library
dialog; your application provides its data and search. See [Images](/docs/getting-started/images)
for the callback adapter.

When neither image callback is provided, handle `request-image`. For files and
video, handle `request-file` and `request-video`. Complete the request with
`request.complete(asset)`, or `request.complete(null)` on cancellation.
Each request can complete once. Cancellation is permanent. Completion returns
`false` if no asset was applied, including an empty source or a changed document,
selection, mode, or editability. Disable unsupported pickers with
`:enable-images="false"`, `:enable-files="false"`, or `:enable-video="false"`.
These flags control insertion; existing media remains readable and removable.
Validate the chosen asset against your content contract before completing it.
Set `image-output="markdown"` for native Markdown image output.

Before navigation or document replacement, await the editor's `flush()` method.
Continue only when it returns `{ ok: true }`, then await your own save operation.
Keep the editor available when flush fails so the author can correct the
document or use Undo. The editor blocks a switch to Markdown while visual edits
cannot be converted safely.

Copy and Cut produce raw Markdown and component source, including titles and
properties. You can share that source with AI tools or paste it back. Text
selected within a title or settings input keeps normal text copying. Markdown paste passes through
Content's parser and the editor's fidelity checks. If a paste cannot preserve
meaning, the editor leaves the document unchanged and shows a message.

The playground saves drafts only in the current browser. It offers Write,
Split view, and Preview modes. Opening an example or a new page offers an Undo
action to recover the previous page. These host behaviors are examples, not
persistence services inside the editor package.

## Customize the writing experience

The default toolbar includes text styles, lists, formatting, code blocks, tables,
and image actions. Use [Customize the editor](/docs/getting-started/customize) to
choose commands, use your own shadcn buttons, change messages and shortcuts, or
place overlays inside a host dialog. Check [Component coverage](/docs/getting-started/component-coverage)
before enabling a Docs component in an authoring kit.
