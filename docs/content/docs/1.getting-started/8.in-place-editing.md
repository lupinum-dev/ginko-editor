# Edit text in place

The inline variant edits text where it appears on the page. It has no frame,
header, or source switch. It uses the host's font, size, color, and spacing, so
the writer sees the final result while writing. The **In place** page of this
site shows three inline editors with different profiles.

```vue [SiteHero.vue]
<script setup lang="ts">
import { ref } from 'vue'
import { GinkoEditor, germanMessages } from '@lupinum/ginko-editor'
import '@lupinum/ginko-editor/style.css'

const title = ref('Fresh pasta, every morning')
const lead = ref('Open **Tuesday to Sunday**.')
</script>

<template>
  <h1>
    <GinkoEditor v-model="title" variant="inline" profile="plain"
      :messages="germanMessages" aria-label="Headline" />
  </h1>
  <GinkoEditor v-model="lead" class="lead" variant="inline" profile="inline"
    :messages="germanMessages" aria-label="Lead" />
</template>
```

## Choose a profile

A profile decides which content a writer can create. The editor reads it once
when it mounts. Remount the editor to use another profile.

| Profile | Allowed content |
| --- | --- |
| `plain` | Paragraphs and line breaks. No formatting. |
| `inline` | `plain`, plus bold, italic, and links. |
| `article` | `inline`, plus headings 2–4, bulleted and numbered lists, quotes, dividers, and images. |
| `full` | All blocks and components. This is the default. |

The profile applies to all input paths:

- The toolbar, the selection toolbar, and the slash menu show only allowed
  commands. The insert button and the slash menu are off for `plain` and `inline`.
- Keyboard shortcuts for other formatting do nothing.
- Markdown input rules, for example `## ` or `- `, create only allowed content.
  A heading at another level moves to the nearest allowed level.
- Paste keeps all text. Headings become paragraphs, lists and tables are
  unwrapped, disallowed formatting is removed, and disallowed media is dropped.

The editor does not change content that it loads from `modelValue`. A document
that already contains other content stays editable. Validate the profile again
where you save the document. See
[Validate content on the server](/docs/getting-started/runtime#enforce-a-content-profile).

## Place the formatting controls

| Prop | Values | Default |
| --- | --- | --- |
| `variant` | `default`, `inline` | `default` |
| `header` | `true`, `false` | `true` for `default`, `false` for `inline` |
| `sourceToggle` | `true`, `false` | `true` for `default`, `false` for `inline` |
| `toolbarPlacement` | `top`, `keyboard`, `auto`, `false` | `top` for `default`, `auto` for `inline` |
| `selectionToolbar` | `auto`, `always`, `false` | `auto` |
| `selectionToolbarItems` | Toolbar groups | Bold, italic, strikethrough, code, link |

`toolbarPlacement="keyboard"` docks the formatting row to the bottom of the
visible screen while the editor has focus. On a phone, the row stays directly
above the on-screen keyboard. Its buttons are 44 pixels high. `auto` uses the
docked row on touch devices. On other devices it uses `top` for the default
variant and no row for the inline variant.

The selection toolbar appears above selected text. `auto` shows it only on
devices with a precise pointer, because phones show their own selection menu.
Items that the profile does not allow are hidden. The toolbar is hidden when
no item remains.

The `toolbar` slot replaces only the top row. The docked row uses
`toolbarItems`.

## Style the inline variant

The inline variant sets no typography. Style the host element as you style the
published page. The editor shows a focus outline around the text. Change it
with these custom properties:

| Property | Default |
| --- | --- |
| `--ginko-inline-focus-outline` | A 2 pixel line in the `--ginko-ring` color |
| `--ginko-inline-focus-offset` | `6px` |
| `--ginko-inline-focus-radius` | `4px` |

The default variant keeps its top row visible while a long document scrolls.
Set `--ginko-sticky-top` to the height of a fixed page header.

The docked row and the selection toolbar use fixed positioning. An ancestor
with `transform`, `filter`, or `contain` changes their reference box. Keep such
styles off the elements around the editor, or set `overlay-container`.
