# Customize the editor

The default toolbar and custom controls use the same guarded actions. Your host
chooses their appearance. The editor owns document validation and changes.

## Choose the toolbar commands

`toolbar-items` is an array of groups. Each group contains commands or a menu.
An empty array hides the main toolbar's commands. It does not disable shortcuts,
the slash menu, or selection controls.

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { GinkoEditor, type EditorToolbarGroup } from '@lupinum/ginko-editor'
import '@lupinum/ginko-editor/style.css'

const source = ref('# Hello\n')
const toolbar = [
  [{ kind: 'undo' }, { kind: 'redo' }],
  [{ kind: 'menu', label: 'Text style', items: [
    { kind: 'paragraph' }, { kind: 'heading', level: 2 },
  ] }],
  [{ kind: 'mark', mark: 'bold' }, { kind: 'link' }],
  [{ kind: 'table', rows: 3, columns: 3 }, { kind: 'codeBlock' }],
] as const satisfies readonly EditorToolbarGroup[]
</script>

<template>
  <GinkoEditor v-model="source" :toolbar-items="toolbar"
    :enable-images="false" :enable-files="false" :enable-video="false" />
</template>
```

| Command | Arguments |
| --- | --- |
| `undo`, `redo`, `paragraph` | None |
| `heading` | `level`: 1–6 |
| `mark` | `mark`: `bold`, `italic`, `strike`, or `code` |
| `bulletList`, `orderedList`, `blockquote`, `codeBlock`, `divider` | None |
| `link` | `href`: URL to apply; empty string removes the link |
| `table` | `rows` and `columns`: integers from 1 to 20; the first row is the header |
| `image`, `file`, `video` | Opens the configured asset flow |
| `insert` | Opens the block insertion menu |

The built-in toolbar opens forms for `link` and `table`. A custom link action
must supply `href`; calling an action does not render a form. A custom table
action inserts its supplied dimensions. Media flags hide unavailable insertion
controls. They do not remove existing media from a document.

## Insert with a slash

Type `/` at the start of a paragraph or after a space. Continue typing to search
block names and keywords. Focus stays in the document. Use the arrow keys to
select a result and Enter to insert it. A successful insertion replaces the
command text in one undo step.

Escape closes the menu and keeps the text you typed. Moving the caret out of the
command or deleting its slash also closes the menu. Code, links, and URLs do not
open it. Text input methods keep their normal composition behavior.

The command position follows document edits before it. If the document or
selection changes while a recipe is being validated, insertion is cancelled and
the typed text stays available. Use Insert to open the same library with a
separate search field. That menu keeps its existing captured-selection guard.

Built-in names and descriptions use `messages`. Host recipe labels, descriptions,
and keywords come from the authoring kit. Search accepts translated labels and
accent-free input and places exact name or keyword matches before partial matches.

A menu uses `{ kind: 'menu', label, items }`. Its items are commands, not nested
menus. A label that matches an `EditorMessages` key uses that translation;
other labels appear as supplied.

## Use a shadcn button

This example assumes your application already has a shadcn-vue `Button` at the
local import path. Keep `ToolbarButton` from Reka around the replacement so it
participates in the toolbar's keyboard navigation. The package does not require
Tailwind or install a component registry in your application.

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { ToolbarButton } from 'reka-ui'
import { GinkoEditor, GinkoToolbar } from '@lupinum/ginko-editor'
import { Button } from '@/components/ui/button'
import '@lupinum/ginko-editor/style.css'

const source = ref('Select some text to format it.')
</script>

<template>
  <GinkoEditor v-model="source" :enable-images="false"
    :enable-files="false" :enable-video="false">
    <template #toolbar="{ actions }">
      <GinkoToolbar :actions="actions">
        <template #bold="{ action }">
          <ToolbarButton v-if="action" as-child>
            <Button type="button" :variant="action.active ? 'secondary' : 'ghost'"
              :disabled="action.disabled" :aria-pressed="action.active"
              :aria-label="action.label" :title="action.shortcut"
              @mousedown.prevent @click="action.run()">
              {{ action.label }}
            </Button>
          </ToolbarButton>
        </template>
      </GinkoToolbar>
    </template>
  </GinkoEditor>
</template>
```

`GinkoToolbar` accepts `actions`, optional `items`, and optional `compact`.
Its slots use the command kind, except marks use `bold`, `italic`, `strike`, or
`code`. Each receives `{ action, actions }`; a `menu` slot has no single action.
It emits `open-change` when one of its menus or forms opens or closes.

The editor's `toolbar` slot receives `{ actions }` and replaces only the main
toolbar. It appears in editable visual mode. A fully custom toolbar owns its
keyboard navigation, accessible labels, forms, and focus restoration.

## Use actions safely

`actions.get(command)` returns an `EditorAction` with these fields:

| Field | Meaning |
| --- | --- |
| `id`, `label`, `shortcut` | Command identity, display label, and optional formatted shortcut |
| `active` | The current selection has this formatting |
| `disabled` | The command cannot run in the current state |
| `available` | The host enables this command's media capability |
| `pending` | This action is validating a document change |
| `value` | Current link address, when the command is `link` |
| `run()` | Returns `Promise<boolean>`; true means accepted, false means no change was applied |

For image, file, and video actions, true means the asset flow opened. Awaiting
`run()` does not await the user's selection or save the document. Use the
editor's `flush()` and then your host's save operation before leaving.

Read actions from the current slot value so their displayed states update.
Prevent mouse-down from moving the editor selection before a formatting click.
For a delayed custom form, call `actions.capture()` when it opens. Run the
command through that captured object. `isCurrent()` becomes false if its document
or selection no longer matches; discard the form in that case. A captured action
is a guard for that context, not a bookmark that follows later edits.

## Theme and overlays

Import `@lupinum/ginko-editor/style.css` once. The editor uses shadcn semantic
variables such as `--background`, `--foreground`, `--muted`,
`--muted-foreground`, `--border`, `--popover`, `--popover-foreground`,
`--accent`, `--accent-foreground`, `--ring`, and `--radius`. Use complete CSS
color values, for example `oklch(...)`. Standalone fallbacks work without a theme.
Put host variables on the editor or an ancestor; keep them scoped when two
editors use different themes.

By default, editor overlays belong to that editor's root. Pass an `HTMLElement`
as `overlay-container` when a host dialog or clipping boundary needs another
portal destination. Set the element after mounting. The editor carries its theme
to its own portal wrapper and removes that wrapper when it unmounts. Each editor
coordinates its own open controls; it does not use one global menu state.
`GinkoImagePicker` is host-controlled and takes its own `overlay-container`.

## Messages and shortcuts

`messages` accepts a partial `EditorMessages` object. Omitted entries use English.
For example, `{ image: 'Bild hinzufügen', chooseImage: 'Bild auswählen' }`
changes the image button and picker title. Pass messages to both components
when you use the standalone `GinkoImagePicker`. Keep interpolation names such
as `{label}`, `{rows}`, and `{columns}` in translated strings. Kit labels,
recipe copy, host errors, and host controls remain the host's responsibility.

`shortcuts` accepts a partial `EditorShortcuts` object. Set a key to `false` to
disable it, or supply a chord such as `Mod-Shift-b`. `Mod` means Command on macOS
and Control on other platforms. Supported modifiers are `Mod`, `Ctrl`, `Meta`,
`Alt`, and `Shift`. Avoid conflicting chords and browser-reserved shortcuts.

| Setting | Default |
| --- | --- |
| `undo` / `redo` | `Mod-z` / `Mod-Shift-z` |
| `bold` / `italic` | `Mod-b` / `Mod-i` |
| `strike` / `code` | `Mod-Shift-s` / `Mod-e` |
| `duplicate` | `Mod-d`, with a block selected |

The default `Alt-Shift-d` duplicates the enclosing component. Overriding
`duplicate` replaces that alias too. Block dragging and block-reordering menus
and shortcuts are not available. Text selections keep normal keyboard selection
behavior. Shortcuts do not run in property inputs or during IME composition.
Platform modifier tests alone do not certify actual Windows or Linux browsers.

## Use the same component in Nuxt

Register the CSS in Nuxt configuration instead of importing it in every page:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  css: ['@lupinum/ginko-editor/style.css'],
})
```

The Vue examples above also work in a Nuxt page. Import `GinkoEditor` and
`GinkoToolbar` explicitly; Editor does not install a Nuxt module or auto-imports.
Keep DOM elements and browser asset work inside the mounted application.
Ginko Docs' optional component kit is a separate host renderer integration.
