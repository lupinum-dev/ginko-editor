# Customize the editor

The default toolbar and custom controls use the same guarded actions. Your host
chooses their appearance. The editor owns document validation and changes.

## Choose the toolbar commands

`toolbar-items` is an array of groups. Each group contains commands or a menu.
An empty array hides the main toolbar's commands. It does not disable shortcuts,
the slash menu, or selection controls.

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { GinkoEditor, type EditorToolbarGroup } from '@lupinum/ginko-editor'
import '@lupinum/ginko-editor/style.css'

const source = ref('# Hello\n')
const toolbar = [
  [{ kind: 'undo' }, { kind: 'redo' }],
  [{ kind: 'menu', label: 'Text style', items: [
    { kind: 'paragraph' }, { kind: 'heading', level: 2 },
  ] }],
  [{ kind: 'mark', mark: 'bold' }, { kind: 'link' }],
  [{ kind: 'table', rows: 3, columns: 3 }, { kind: 'codeBlock' }],
] as const satisfies readonly EditorToolbarGroup[]
</script>

<template>
  <GinkoEditor v-model="source" :toolbar-items="toolbar"
    :enable-images="false" :enable-files="false" :enable-video="false" />
</template>
```

| Command | Arguments |
| --- | --- |
| `undo`, `redo`, `paragraph` | None |
| `heading` | `level`: 1–6 |
| `mark` | `mark`: `bold`, `italic`, `strike`, or `code` |
| `bulletList`, `orderedList`, `blockquote`, `codeBlock`, `divider` | None |
| `link` | `href`: URL to apply; empty string removes the link |
| `table` | `rows` and `columns`: integers from 1 to 20; the first row is the header |
| `image`, `file`, `video` | Opens the configured asset flow |
| `insert` | Opens the block insertion menu |

The built-in toolbar opens forms for `link` and `table`. A custom link action
must supply `href`; calling an action does not render a form. A custom table
action inserts its supplied dimensions. Media flags hide unavailable insertion
controls. They do not remove existing media from a document.

## Insert with a slash

Type `/` at the start of a paragraph or after a space. Continue typing to search
block names and keywords. Focus stays in the document. A successful insertion
replaces the command text in one undo step.

Escape closes the menu and keeps the text you typed. Moving the caret out of the
command or deleting its slash also closes the menu. Code, links, and URLs do not
open it. Text input methods keep their normal composition behavior.

The command position follows document edits before it. If the document or
selection changes while a recipe is being validated, insertion is cancelled and
the typed text stays available. Use Insert to open the same library with a
separate search field. That menu keeps its existing captured-selection guard.

### Groups and ranking

The menu shows results in groups: **Text**, **Lists**, **Media**, **Layout**,
**Callouts**, the groups of your kits, **Components**, and **Advanced**. With a
search, the group with the best result comes first. Results rank in this order:

1. The name or a keyword is the search text.
2. The name starts with the search text.
3. Each search word starts a word of the name.
4. A keyword, the description, or the id contains the search text.
5. The letters of the search text occur in the name in the same order.

Results with the same rank keep their kit order. The matched letters of each
name are underlined.

Without a search, the menu shows up to five recently inserted blocks first. The
editor keeps this list in memory for each editor. When the caret is inside a
container item, for example a tab, the menu first offers the add action of that
container, for example **Add tab**.

### Keyboard

| Key | Action |
| --- | --- |
| Up and Down arrows | Select the previous or next result. The selection wraps. |
| Home and End | Select the first or last result. |
| Enter | Insert the selected result. |
| Tab | Move focus to the `recipe-preview` area, when you supply one. Tab again returns focus. |
| Escape | Close the menu and keep the typed text. |

The results are a listbox with labelled groups. The document or the search field
refers to the selected result with `aria-activedescendant`. The pointer selects a
result only when it moves, so keyboard scrolling does not change the selection.

### Recipe fields

Built-in names, descriptions, and group names use `messages`. Host recipe
labels, descriptions, and keywords come from the authoring kit. A recipe can
also set `group` and `icon`:

```ts [recipe.ts]
const recipe = {
  id: 'objective',
  label: 'Learning objective',
  group: 'Teaching',
  icon: 'list-checks',
  source: '::learning-objective{title="Understand the contract"}\nExplain the outcome.\n::',
}
```

`group` is a built-in group name (`text`, `lists`, `media`, `layout`,
`callouts`, or `advanced`) or the heading of your own group. Recipes without a
group appear in **Components**. `icon` is a Lucide icon name in kebab-case. The
editor bundles a small set of icons. Other names show a generic block icon.
Search accepts translated labels and accent-free input.

A menu uses `{ kind: 'menu', label, items }`. Its items are commands, not nested
menus. A label that matches an `EditorMessages` key uses that translation;
other labels appear as supplied.

## Use a shadcn button

This example assumes your application already has a shadcn-vue `Button` at the
local import path. Keep `ToolbarButton` from Reka around the replacement so it
participates in the toolbar's keyboard navigation. The package does not require
Tailwind or install a component registry in your application.

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { ToolbarButton } from 'reka-ui'
import { GinkoEditor, GinkoToolbar } from '@lupinum/ginko-editor'
import { Button } from '@/components/ui/button'
import '@lupinum/ginko-editor/style.css'

const source = ref('Select some text to format it.')
</script>

<template>
  <GinkoEditor v-model="source" :enable-images="false"
    :enable-files="false" :enable-video="false">
    <template #toolbar="{ actions }">
      <GinkoToolbar :actions="actions">
        <template #bold="{ action }">
          <ToolbarButton v-if="action" as-child>
            <Button type="button" :variant="action.active ? 'secondary' : 'ghost'"
              :disabled="action.disabled" :aria-pressed="action.active"
              :aria-label="action.label" :title="action.shortcut"
              @mousedown.prevent @click="action.run()">
              {{ action.label }}
            </Button>
          </ToolbarButton>
        </template>
      </GinkoToolbar>
    </template>
  </GinkoEditor>
</template>
```

`GinkoToolbar` accepts `actions`, optional `items`, and optional `compact`.
Its slots use the command kind, except marks use `bold`, `italic`, `strike`, or
`code`. Each receives `{ action, actions }`; a `menu` slot has no single action.
It emits `open-change` when one of its menus or forms opens or closes.

The editor's `toolbar` slot receives `{ actions }` and replaces only the main
toolbar. It appears in editable visual mode. A fully custom toolbar owns its
keyboard navigation, accessible labels, forms, and focus restoration.

## Use actions safely

`actions.get(command)` returns an `EditorAction` with these fields:

| Field | Meaning |
| --- | --- |
| `id`, `label`, `shortcut` | Command identity, display label, and optional formatted shortcut |
| `active` | The current selection has this formatting |
| `disabled` | The command cannot run in the current state |
| `available` | The host enables this command's media capability |
| `pending` | This action is validating a document change |
| `value` | Current link address, when the command is `link` |
| `run()` | Returns `Promise<boolean>`; true means accepted, false means no change was applied |

For image, file, and video actions, true means the asset flow opened. Awaiting
`run()` does not await the user's selection or save the document. Use the
editor's `flush()` and then your host's save operation before leaving.

Read actions from the current slot value so their displayed states update.
Prevent mouse-down from moving the editor selection before a formatting click.
For a delayed custom form, call `actions.capture()` when it opens. Run the
command through that captured object. `isCurrent()` becomes false if its document
or selection no longer matches; discard the form in that case. A captured action
is a guard for that context, not a bookmark that follows later edits.

## Theme and overlays

Import `@lupinum/ginko-editor/style.css` once. All editor styles are in the
`ginko` cascade layer. A host rule outside a cascade layer overrides them,
independently of selector specificity.

The editor reads its colors and sizes from public `--ginko-*` tokens. Each color
token uses the matching shadcn variable when your application defines it, and a
neutral fallback when it does not. The editor declares the tokens once, on its
outermost element. To change a token, set it on `.ginko-editor` or an ancestor
element that you control:

```css
.article-editor .ginko-editor {
  --ginko-primary: oklch(0.45 0.18 260);
  --ginko-radius: 0.375rem;
}
```

Use complete CSS color values, for example `oklch(...)`. Keep variables scoped
when two editors use different themes.

| Token | Default source | Use |
| --- | --- | --- |
| `--ginko-background` | `--background`, `#fff` | Editor and panel background |
| `--ginko-foreground` | `--foreground`, `#171717` | Text |
| `--ginko-muted` | `--muted`, `#f5f5f5` | Hover and code backgrounds |
| `--ginko-muted-foreground` | `--muted-foreground`, `#737373` | Secondary text |
| `--ginko-border` | `--border`, `#e5e5e5` | Borders and separators |
| `--ginko-input` | `--input`, `--ginko-border` | Form field borders |
| `--ginko-accent` | `--accent`, `#f5f5f5` | Active and highlighted controls |
| `--ginko-accent-foreground` | `--accent-foreground` | Text on accent backgrounds |
| `--ginko-primary` | `--primary`, `#171717` | Primary buttons |
| `--ginko-primary-foreground` | `--primary-foreground`, `#fafafa` | Text on primary buttons |
| `--ginko-destructive` | `--destructive`, `#b42318` | Errors and delete actions |
| `--ginko-popover` | `--popover`, `--ginko-background` | Menus and tooltips |
| `--ginko-popover-foreground` | `--popover-foreground` | Menu text |
| `--ginko-ring` | `--ring`, `#737373` | Focus outlines |
| `--ginko-radius` | `--radius`, `0.625rem` | Corner radius |
| `--ginko-warning`, `--ginko-warning-background`, `--ginko-warning-foreground` | Built in | Conversion and shared state notices |
| `--ginko-selection` | Built in | Selected table cells |
| `--ginko-tone-neutral`, `-info`, `-warning`, `-danger`, `-success`, `-idea` | Built in | Component tone accents |
| `--ginko-shadow-sm`, `--ginko-shadow-md`, `--ginko-shadow-lg` | Built in | Toolbars, panels, and menus |
| `--ginko-overlay-backdrop` | Built in | Image picker backdrop |
| `--ginko-z-menu`, `--ginko-z-floating`, `--ginko-z-popover`, `--ginko-z-dropdown`, `--ginko-z-tooltip` | 50, 100, 200, 250, 300 | Stacking order of overlays |

### Dark mode

When your application defines shadcn variables for dark mode, the editor uses
them. You need no other setup. Without shadcn variables, the editor uses its dark
fallbacks in these cases:

- An ancestor element, or the editor, has the `dark` class.
- An ancestor element, or the editor, has `data-ginko-theme="dark"`.
- An ancestor element, or the editor, has `data-ginko-theme="auto"`, and the
  operating system prefers a dark color scheme.

The editor does not follow the operating system setting unless you set
`data-ginko-theme="auto"`. This prevents a dark editor inside a light page.

By default, editor overlays belong to that editor's root. Pass an `HTMLElement`
as `overlay-container` when a host dialog or clipping boundary needs another
portal destination. Set the element after mounting. The editor carries its theme
to its own portal wrapper and removes that wrapper when it unmounts. Each editor
coordinates its own open controls; it does not use one global menu state.
`GinkoImagePicker` is host-controlled and takes its own `overlay-container`.

## Messages and shortcuts

`messages` accepts a partial `EditorMessages` object. Omitted entries use English.
The exported `defaultMessages` object lists every key and its English text.
`EditorMessageKey` is the type of these keys. The keys include the default
accessible name `contentLabel`, the source field name `markdownSourceLabel`, and
the empty document text `startWriting`. Interface text changes immediately when
you pass new messages.
For example, `{ image: 'Bild hinzufügen', chooseImage: 'Bild auswählen' }`
changes the image button and picker title.

The package includes a complete German set, `germanMessages`. Its instructions
use the infinitive, so it fits sites that use "du" and sites that use "Sie".
Spread it to change single entries:
`:messages="{ ...germanMessages, startWriting: 'Was gibt es Neues?' }"`. Pass messages to both components
when you use the standalone `GinkoImagePicker`. Keep interpolation names such
as `{label}`, `{rows}`, and `{columns}` in translated strings. Kit labels,
recipe copy, host errors, and host controls remain the host's responsibility.

`shortcuts` accepts a partial `EditorShortcuts` object. Set a key to `false` to
disable it, or supply a chord such as `Mod-Shift-b`. `Mod` means Command on macOS
and Control on other platforms. Supported modifiers are `Mod`, `Ctrl`, `Meta`,
`Alt`, and `Shift`. Avoid conflicting chords and browser-reserved shortcuts.

| Setting | Default |
| --- | --- |
| `undo` / `redo` | `Mod-z` / `Mod-Shift-z` |
| `bold` / `italic` | `Mod-b` / `Mod-i` |
| `strike` / `code` | `Mod-Shift-s` / `Mod-e` |
| `duplicate` | `Mod-d`, with a block selected |

The default `Alt-Shift-d` duplicates the enclosing component. Overriding
`duplicate` replaces that alias too. Block dragging and block-reordering menus
and shortcuts are not available. Text selections keep normal keyboard selection
behavior. Shortcuts do not run in property inputs or during IME composition.
Platform modifier tests alone do not certify actual Windows or Linux browsers.

## Use the component handle

Get the component handle with a template ref. The handle has the type
`GinkoEditorHandle`:

| Method | Result |
| --- | --- |
| `flush()` | Emits pending visual edits. Returns `{ ok: true, emitted }` or `{ ok: false, error }`. |
| `hasPendingChanges()` | True while edits, image operations, commands, or shared steps are pending. |
| `removeSelectedMedia()` | Removes the selected image, file, or video. Returns false when nothing was removed. |
| `focus(position?)` | Moves focus into the editor. Use `'start'` or `'end'` to move the caret. |
| `getEditor()` | Returns the TipTap editor, or `undefined` before it exists. |

A flush `error` is either a `ConversionErrorPayload` or an editor state error
`{ code, message }`. The state codes are `image_upload_pending`,
`collaboration_pending`, and `not_ready`. Conversion codes have the type
`ConversionIssueCode`. Check `code` to find the cause.

`getEditor()` is an unstable escape hatch. Its API follows TipTap and the editor
schema and can change in any release. Do not use it to dispatch changes that skip
the editor's validation. To insert assets, use the request events.

```vue
<script setup lang="ts">
import { ref, useTemplateRef } from 'vue'
import { GinkoEditor } from '@lupinum/ginko-editor'

const source = ref('')
const editor = useTemplateRef<InstanceType<typeof GinkoEditor>>('editor')

async function save() {
  const result = await editor.value?.flush()
  if (!result?.ok) return
  // Await your application's save operation here.
}
</script>

<template>
  <GinkoEditor ref="editor" v-model="source" />
</template>
```

All props are reactive, except `collaboration`. The editor reads a shared
session once when it mounts. To use another session, remount the editor, for
example with a new `key`. In development builds, the editor writes a console
warning when the `collaboration` prop changes.

Inline functions and objects are safe to pass. A new `image-upload` or
`image-picker` function, a new `asset-provider` object, or an equal new authoring
kit does not cancel uploads, invalidate asset requests, or reload the document.
Only a removed capability, a disabled editor, a mode change, or a changed Content
policy does that. A kit with new labels or recipes but the same policy updates
the interface and keeps the document.

## Use the same component in Nuxt

Register the CSS in Nuxt configuration instead of importing it in every page:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  css: ['@lupinum/ginko-editor/style.css'],
})
```

The Vue examples above also work in a Nuxt page. Import `GinkoEditor` and
`GinkoToolbar` explicitly; Editor does not install a Nuxt module or auto-imports.
Keep DOM elements and browser asset work inside the mounted application.
Ginko Docs' optional component kit is a separate host renderer integration.
