# Share an editing session

Ginko Editor can share a document through a host transport. It uses ProseMirror
operations to merge text changes. The host owns authentication, authorization,
storage, recovery files, and publication. The editor does not open a Convex
connection or create accounts.

The package provides two boundaries:

- `@lupinum/ginko-editor/collaboration`: a Vue-compatible editing session and
  transport types.
- `@lupinum/ginko-editor/runtime`: the shared schema, strict operation decoding,
  and server checkpoint validation. This entry does not import Vue views or
  browser globals.

Use the same Editor package and Content policy on the client and server. A
schema revision identifies the operation format. A policy revision identifies
the host's permitted components and properties. An epoch identifies one
generation of a document. Replacing a document starts a new epoch.

## Mount one session

The host first opens an authorized document and obtains its current snapshot.
It supplies three transport operations: subscribe to the current head, pull
accepted operations, and push a batch at an exact version.

```ts
import { createEditorCollaboration } from '@lupinum/ginko-editor/collaboration'

const session = createEditorCollaboration({
  snapshot: opened.snapshot,
  clientId: opened.clientPrefix + crypto.randomUUID(),
  transport,
  recovery: savedRecovery,
  onRecovery(value) {
    if (value) sessionStorage.setItem(recoveryKey, JSON.stringify(value))
    else sessionStorage.removeItem(recoveryKey)
  },
})
```

```vue
<GinkoEditor
  v-model="sourcePreview"
  :collaboration="session"
  :authoring-kit="authoringKit"
/>
```

Keep the session in a `shallowRef` or an ordinary variable. Do not make its
internal editor state deeply reactive. One session belongs to one mounted
editor. Create a new session and remount when switching documents, epochs, or
content policies. Await `flush()` before leaving; keep the editor mounted if
flush fails.

In shared mode, the session snapshot supplies the initial document. `v-model`
receives a source preview. Changes to that prop do not replace the shared
document. Source view is read-only. A successful `flush()` means all pending
operations have been accepted and the local source preview is current. It does
not publish content. Another writer can still edit after the flush.

The default status shows connecting, saving, saved, offline, and recovery
states. The `collaboration` slot receives `state` and `session` if the host
needs its own status control. Use `session.subscribe()` for application state
and call the returned cleanup function when the host unmounts.

## Validate each write

The backend checks document access on every read and write. Do not trust a
room ID, client ID, source preview, or snapshot supplied by a browser.

```ts
import { applyCollaborationSteps } from '@lupinum/ginko-editor/runtime'

const accepted = await applyCollaborationSteps(storedSnapshot, batch, {
  policy: hostPolicy,
  output: hostOutputOptions,
})

// In one database transaction:
// 1. Store accepted.snapshot.
// 2. Append the accepted operations and authenticated client identity.
// 3. Store accepted.markdown with the same epoch and version.
```

`applyCollaborationSteps()` rejects an incorrect version or document fence,
unknown operations, malformed positions, unknown schema attributes, unsupported
metadata, and results outside the Content policy. It derives Markdown from the
accepted document. It never accepts a browser's Markdown checkpoint.

Seed or replace a room with `createCollaborationSnapshot()`. It refuses source
that requires source-only editing. A replacement must check the current fence
and version in the same authorized transaction, then start a new epoch. Keep
old published content until the host explicitly publishes the replacement.

For Convex, query the current head reactively with `ConvexClient.onUpdate()` and
use generated, typed query and mutation references for pull and push. Check
the membership or document permission inside each function. Scope client IDs
to the authenticated member and add a random identifier for each session.
Return accepted operations after a version conflict so the editor can rebase
and retry. Do not use last-write-wins Markdown updates.

The repository's `test/fixtures/convex-collaboration` directory contains an
executable local example with signed test identities. It demonstrates
authorization, bounded history reads, version conflicts, revocation,
replacement, publication, and pruning. Its test authentication and membership
tables are fixture code. Use the host application's real authentication and
document permissions in an application.

## Store checkpoints and history separately

Store the ProseMirror document as an encoded JSON string. Its nested tree must
not become deeply nested database fields. Store the derived source in a
separate record when the two representations could exceed the database's
document-size limit. Both records carry the same epoch and version.

The server snapshot is the authority for the active editing session. Markdown
is a derived, versioned checkpoint for Content readers, export, and
publication. It can be rebuilt from the snapshot. Do not independently edit
both representations.

Publish an exact `{ epoch, version }` checkpoint after checking that it is still
current. Record the publication epoch as well as its version: version numbers
restart after replacement. A failed comparison requires the host to refresh
and show the newer draft.

History queries must use an index and a bounded page. The provided protocol
limits a document to 512 KiB, a batch to 256 KiB, and a batch to 128 operations.
A client keeps each original transaction in one outgoing batch. Read pages
must preserve operation order and return their actual start and end versions.

Set an explicit retention policy in the host. Keep a minimum retained version.
If a disconnected client needs older operations, return `status: 'stale'` with
reason `history`. Do not silently discard its pending edits or substitute a new
snapshot. Delete old log pages in bounded jobs. Replacing a document also
requires eventual cleanup of the old epoch's log.

## Recover pending changes

Supply `onRecovery` when unsent edits must survive reload. The callback runs
synchronously after document changes. Persist the value in host-owned browser
storage; throwing stops editing and keeps the current document available. The
editor does not promise durable recovery when this callback is omitted.

A recovery copy includes the confirmed base, pending operations, transaction
groups, and the resulting document. Reopening checks its format and document
fence, then rebases pending operations over accepted server history. A lost
acknowledgement does not duplicate an accepted operation.

Use `parseCollaborationRecovery(storedJson)` to read untrusted storage into a
typed recovery value. Session construction then checks the document, operations,
limits, and fences. Keep an invalid copy available for download; do not silently
discard it or enable a fresh writable session over it.

Only one live session may own a client ID. Browsers can copy `sessionStorage`
when a tab is duplicated or opened from another tab. Claim an exclusive Web Lock
for the client ID before opening either a new or recovered session, and release
it after closing that session. If another tab owns the ID, offer the recovery
download and a deliberate reopen with a new identity. Do not replay the same
pending operations under a second identity.

The client bounds recovery to 2,048 pending operations, 2 MiB of encoded
operations, and a 4 MiB recovery budget for local changes. Rebased remote
changes can enlarge a recovery file; reopening accepts up to 16 MiB. A local change that would
exceed a limit is refused before replacing the local document. Reconnect to
continue writing. The limits describe recovery capacity, not an offline-first
database.

Use `CollaborationConnectionError` for a connection failure. The session keeps
local edits and retries with backoff. Other transport errors stop automatic
retries. Revoked access, a changed schema or policy, a new epoch, or expired
history must remain visible. The default control can download the pending
recovery JSON. Keep that copy before reopening or importing its content into a
new document. Never apply old operations to a different epoch automatically.

## Understand concurrent controls

Body text merges through ProseMirror. Component controls change individual
properties. Independent properties preserve each other; two changes to the
same property use the last accepted operation. Titles in separate property
inputs are field updates, not character-level shared text. Code language and
filename controls also update separate fields. Image replacement preserves
unrelated properties, including another writer's description.

Shared tables support cell editing and inserting, deleting, or
duplicating body rows. Column layout, alignment changes, and row moves are disabled during a shared
session. ProseMirror does not preserve pending edits through arbitrary node
moves, and concurrent row and column layout changes can produce incompatible
rectangles. Local tables retain their full controls. Merged cells and custom
cell widths are rejected because the Content checkpoint cannot preserve them.

Presence and remote selection decorations are separate from document
operations. The session does not currently provide them. Host presence records
must expire and use the same document authorization. Do not treat an avatar as
proof that a writer's changes have been accepted.
